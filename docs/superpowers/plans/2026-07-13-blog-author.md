# Blog Author Feature Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a managed Authors concept end-to-end: a CMS Authors collection, a single-optional author relationship on BlogPosts (rendered as a select dropdown), and an author card on the public blog post page (image left, info right, last thing before the footer).

**Architecture:** Payload CMS 3.80 auto-generates the admin UI from collection configs — a new `Authors` collection plus a `relationship` field on `BlogPosts` yields a searchable author select with no custom UI. The web app already fetches blog posts at `depth=2`, so the author and its media photo populate for free. A new `BlogAuthor` Astro component renders the card before the footer.

**Tech Stack:** Payload CMS 3.80 (Next.js 16, Postgres), Astro 5.x, TypeScript strict, Phosphor Icons (CDN), plain CSS per CONVENTIONS.md. No test framework exists in this repo — verification is via Payload type generation (`generate:types`), Astro build (`astro build`), and manual dev-server checks.

## Global Constraints

- **CMS framework:** Payload CMS 3.80 on Next.js 16; collections are config files in `apps/cms/src/collections/`. No Prisma; Postgres via `@payloadcms/db-postgres`.
- **Web framework:** Astro 5.x; pages live in `apps/web/src/pages/`, components in `apps/web/src/components/`.
- **Styling:** 1 component = 1 `.astro` + 1 `.css` in `apps/web/src/styles/`. Repeat `:root` vars (`--yellow-color: #FAD02C; --dark-blue-color: #19304B;`) at the top of each CSS file. Use `clamp()`/`min()` for responsive sizing. **No `border-radius`** on cards. Include `:focus-visible` and `@media (prefers-reduced-motion: reduce)`. No Tailwind, no scoped `<style>`.
- **Icons:** Phosphor via CDN class `ph ph-{name}`.
- **Language:** Spanish labels/content; English class/variable names.
- **Shared types:** `packages/shared/src/index.ts` is the single source the web app imports via `@fusion-legal/shared`.
- **No test runner in the repo.** Do not introduce one. Verify via type-gen + build + dev server.
- **Commit style:** match repo: `feat:`, `docs:`, etc., lowercase imperative.
- **Run commands from the workspace root** `C:\Users\Josue\Documents\GitHub\fl-webpage` unless a step says otherwise; use `--workspace=` for npm scripts.

```ts
  console.log('Seeding authors...')
  const logoPath = path.resolve(__dirname, 'public', 'fl_logo.webp')
  const logoBuffer = fs.readFileSync(logoPath)
  for (const author of authors) {
    // Upload a media photo for this author
    const media = await payload.create({
      collection: 'media',
      data: { alt: `Foto de ${author.name}` },
      file: {
        data: logoBuffer,
        mimetype: 'image/webp',
        name: `author-${author.name.toLowerCase().replace(/\s+/g, '-')}.webp`,
        size: logoBuffer.length,
      },
    })
    await payload.create({
      collection: 'authors',
      data: {
        ...author,
        photo: media.id,
      },
    })
  }
  console.log(`✓ ${authors.length} authors created`)
```
